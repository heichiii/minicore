# M6：VFS、文件描述符、管道和用户内存区域

本阶段按 `roadmap-v2.md` 实现。运行 `make test`，会在 256 MiB、32 MiB 两种
QEMU 配置下执行 M1–M6 验收；`make run` 展示完整启动输出并自动退出。
系统调用编号、边界和错误语义见 [syscall-abi.md](syscall-abi.md)。

## 1. 文件对象的三层关系

`src/fs/vfs.h` 区分三个对象：`vnode` 表示命名空间中的文件或目录；`file`
表示一次打开，保存 offset、打开标志、引用计数和后端操作；`mount` 把一个
文件系统根连接到被覆盖目录。进程的 `fds[32]` 保存 `file *`。

例如两次 `open("/tmp/data")` 得到两个 file，各自从 offset=0 开始；`dup(fd)`
增加同一个 file 的引用，因此两个 fd 共用 offset。fork 复制 fd 表并逐项增加
引用，也保留这种共享关系。close 清空一个槽并减少引用；只有最后一次
file_put 才执行后端 release。exec 保留 fd 表、root 和 cwd。

当前没有 unlink/unmount，所有 vnode 活到命名空间关闭，所以 file、cwd/root
可以借用 vnode 指针。这个生命周期约束写在头文件中；将来增加删除操作时，
需要补 vnode 引用计数，不能照搬现在的借用方式。

## 2. 路径、挂载与后端

`vfs_resolve` 逐段处理路径。绝对路径从 root 开始，相对路径从 cwd 或 openat
指定的目录开始。普通名称查找目录子节点；遇到挂载点进入挂载根；在挂载根
处理 `..` 时跨回覆盖目录的父目录。root 处的 `..` 留在 root。

软链接用有界缓冲区迭代展开，最多八次，不递归消耗内核栈。相对目标从链接
所在目录开始，绝对目标从 root 开始。测试覆盖普通链接、目录链接、绝对链接、
悬空链接、循环链接、重复斜线和尾部斜线。

启动挂载只读 initramfs 到 `/`，可写内存文件系统到 `/tmp`，设备目录到 `/dev`。
tmpfs 每文件最多 16 页，按写入位置分配物理页，空洞读零；它没有持久化承诺。
console、null、普通文件和管道都通过 file_ops 访问。`src/kernel/fd.c` 只做 fd
查找、用户指针检查和数据搬运，不直接访问 UART。

read/write 先验证整个用户区间，再用 256 字节内核缓冲区搬运。这样坏指针不会
先消耗管道数据或推进文件 offset。可睡眠 I/O 临时持有 file 引用。当前每进程
只有一个用户线程，且没有共享地址空间，因此睡眠期间地址映射不会被另一个
线程修改。以后实现多线程共享 VM 时，需要重新设计这部分保护。

## 3. 管道为什么不会提前关闭

`src/fs/pipe.c` 为每根管道创建两个 file：读端和写端，二者指向同一个 512 字节
环形缓冲区。dup/fork 只增加 file 引用，不增加独立端点对象。读端最后一个引用
释放时标记“无读者”，唤醒写者；写端同理。两端都消失后才释放管道本体。

空管道且仍有写者时，读线程加入 readable 等待队列；满管道且仍有读者时，写
线程加入 writable 队列。检查条件、入队与释放锁按 wait_queue 的协议完成，
醒来后用 while 重新检查条件，避免丢失唤醒。写者全部关闭后先读完剩余数据，
再返回 EOF；读者全部关闭后 write 返回 -EPIPE，不发送信号。

进程退出仍由调度器在另一条内核栈上回收；回收所有 fd 会触发相同的关闭与唤醒
逻辑。因此“不显式 close 直接 exit”也能让对端结束等待。

## 4. VMA、页表和物理页账本各管什么

`address_space` 现在维护三个不同层面的对象：

| 对象 | 职责 |
|---|---|
| `areas` / VMA | 哪些虚拟区间已预留、权限和区域类型是什么 |
| `table` / Sv39 | CPU 如何翻译地址和检查权限 |
| `pages` / user_page | 哪些物理页由这个地址空间负责释放 |

三者不能合并：PROT_NONE 有 VMA 和物理页，但没有可访问的硬件叶子；栈保护页
属于预留区间，却没有物理页；munmap 切分 VMA 只改区间元数据，不复制幸存页面。

ELF 加载时登记段与栈的 VMA；堆从 0x800000 开始；mmap 在
`[0x10000000,0x20000000)` 选择空闲区间。所有映射立即分配，不做缺页加载。
文件 mmap 是私有快照：pread 不改 file offset，完成后不持有 file 引用，关闭
原 fd 不影响映射。fork 深拷贝 VMA、页和 brk 元数据；exec 事务性替换整个空间。

brk 保存精确字节边界，但以页为单位增减内存。munmap 先检查整个区间，拒绝
覆盖 ELF、栈和堆；中间挖洞时先分配新的 VMA，成功后再拆分旧区间和释放页。
这样元数据分配失败不会留下半拆的地址空间。映射失败会撤销新页与新 VMA，
`vm_prune_user` 清理页表创建中途遗留的空分支，不触碰共享的高半内核映射。

## 5. shell 的一次实际执行

用户态 `user/sh.c` 支持最多四段管道、每段八个参数、`cd`、`<`、`>` 和 `>>`。
没有引号、变量展开、后台任务或作业控制。无斜线的程序名在 `/bin` 查找；含
斜线的名称按原路径执行。`-c` 执行一条命令，无参数时逐行读取 stdin。

例如 `echo hello world|upper>/tmp/out`：

1. shell 解析两个命令，创建一根管道。
2. fork 第一个子进程，把管道写端 dup2 到 fd 1，再 exec `/bin/echo`。
3. fork 第二个子进程，把管道读端 dup2 到 fd 0，打开 `/tmp/out` 并 dup2 到
   fd 1，再 exec `/bin/upper`。
4. 两个子进程都关闭继承的原始管道 fd；shell 也关闭自己的两端。
5. echo 写入并退出；upper 读到 EOF 后退出。shell 启动所有阶段后才 wait，
   避免生产者写满管道时消费者还没创建的死锁。

`echo`、`cat`、`upper` 是独立 ELF。`user/crt.S` 从初始栈读取参数，调用 C main；
`user/lib.c` 封装 ecall 和短写重试，不依赖宿主 libc。

## 6. 验收与失败路径

`user/m6-test.c` 从 U-mode 检查 fd 最低空槽分配、dup/fork 共享 offset、独立
open、只读根、tmpfs 空洞、append、目录遍历、cwd 继承、坏指针、满 fd 表时
O_TRUNC 不修改文件。管道测试覆盖超过容量的传输、EOF/EPIPE、睡眠时关闭、
四个并发子进程写入和重复引用释放。

VM 测试覆盖 heap 增减、匿名映射、文件私有快照、不改变文件 offset、PROT_NONE、
只读访问故障、无效参数、固定地址冲突、munmap 全删/前裁/后裁/中间切分、
重新利用空洞、fork 隔离和 exec 释放旧映射。shell 测试覆盖多级管道、三种
重定向、缺失输入、语法错误、相对 exec，以及 stdin 脚本中的 cd。

内核额外耗尽物理页，然后逐步给出 0–24 页预算，检查 ELF、地址空间复制、
mmap、brk、pipe 分配路径。每次操作后比较空闲页数；最后 init 退出，检查
打开文件数量为零，再销毁命名空间，确认物理页数精确回到挂载前。

这套实现仍依赖单 hart 的关中断保护 offset/引用计数；SMP、共享 mmap、按需
分页、持久化文件系统和动态挂载不属于本阶段。
