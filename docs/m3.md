# M3: first U-mode program

The test program is linked separately at `0x10000`, converted to a flat image,
and embedded in the kernel. Each run receives a fresh lower-half address space
while sharing the kernel's upper-half page-table branches. Teardown frees all
user pages and private page-table pages.

The trap entry swaps from the user stack to a saved kernel stack via
`sscratch` before storing registers. Syscall and exception completion return to
the kernel through the same trap frame. M3 has no scheduler and therefore only
one active user context.

The acceptance sequence runs three fresh processes:

1. A program writes a buffer spanning two user pages, verifies that an unmapped
   write buffer returns `-EFAULT`, and exits with status zero.
2. A load from the upper-half kernel direct map terminates only that process
   with a user load-page-fault result.
3. A store into the RX user text page terminates only that process with a user
   store-page-fault result.

Both 256 MiB and 32 MiB QEMU configurations must print `M3 PASS`. The page
allocator count is checked after all three processes to catch address-space or
image-page leaks.
