# M1: DTB, traps and time

M1 keeps platform discovery separate from RISC-V trap mechanics:

- `platform/dtb.c` validates the flattened-device-tree header, block bounds,
  structure, and properties. It copies RAM and reserved ranges (including the
  reservation table), timebase frequency, UART, PLIC, and VirtIO-MMIO details
  into `boot_info` before the original DTB can be reclaimed.
- `arch/riscv/trap.S` builds a 288-byte, 16-byte-aligned trap frame containing
  `x0` through `x31`, `sepc`, `sstatus`, `scause`, and `stval`. The C dispatcher
  may update `sepc` and `sstatus`; `sret` restores the remaining state.
- `arch/riscv/sbi.c` contains SBI calls. Boot probes the SBI TIME extension
  before using absolute timer events. S-mode never writes the ACLINT/CLINT
  timer directly.
- `platform/plic.c` exposes QEMU `virt` supervisor-context initialization,
  source enable/disable, claim, and completion. No external source is enabled
  yet; UART and VirtIO will use this interface in later milestones.

The trap entry currently handles traps originating in S-mode on the boot
stack. Before M3 enters U-mode, it must gain a per-thread kernel stack switch
(normally using `sscratch`) and establish a kernel-owned `tp` value before
calling C. The entry already reloads the kernel `gp` after saving the trapped
value.

## Boot self-test

The kernel performs the following checks during boot and prints `M1 PASS` on
success:

1. reports the RAM extent discovered from the QEMU DTB;
2. deliberately executes a write to the read-only `cycle` CSR, an `ebreak`,
   and a load from address zero, checking causes 2, 3, and 5;
3. programs periodic one-shot events through SBI TIME; and
4. takes three timer interrupts inside a register test that gives every
   integer register a known value and validates the complete saved frame.

In Linux terms, this stage corresponds to early FDT scanning, architecture
entry code (`handle_exception`), `pt_regs`, clock-event programming, and the
irqchip-facing PLIC operations. MiniCore deliberately has one boot stack, one
hart, no generic IRQ descriptor layer, and no scheduler-driven timer consumer
at this stage.
