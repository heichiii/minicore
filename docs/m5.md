# M5: read-only userspace and process lifecycle

M5 boots `/init` from a build-generated, read-only `newc` initramfs. Programs
are separate static ELF64 files and no longer use a flat binary embedded as a
special user image. The initramfs currently contains `/init`, `/bin/child`,
three fault programs, and one malformed executable used by acceptance tests.

## Storage and ELF loading

The minimal VFS parses the archive once into `vnode` objects. Absolute lookup
opens regular files as reference-counted `file` objects, and `file_pread`
provides the only interface needed by the ELF loader. The loader therefore has
no dependency on archive layout and can later read from another filesystem.

The loader accepts little-endian RV64 static `ET_EXEC` images. It validates all
header and segment ranges, rejects dynamic interpreters and W+X segments, maps
each `PT_LOAD` with its final permissions, leaves BSS zeroed, and requires the
entry point to lie in an executable segment. Four RW/NX stack pages end at
`0x400000`; the page below is a guard. Strings and the conventional
`argc/argv/envp` vectors are placed on a 16-byte-aligned initial stack.

An exec first copies its bounded path and argument vectors out of the old user
address space. It then constructs the entire replacement image independently.
Only after every allocation, read, mapping, and stack write succeeds does it
activate the new page table and destroy the old one. PID, children, parent, and
descriptor references survive the commit. Any failure returns to the old
program unchanged.

## Process lifetime

Each process owns one thread, a private lower-half address space, three file
slots, a PID, parent/child links, exit state, and a child wait queue. `fork`
eagerly copies each owned user page and clones the interrupted trap frame; the
child's `a0` is changed to zero before its thread is published. Descriptor
objects are shared by reference.

Exit has two phases. The exiting thread records its status, becomes a zombie,
adopts its children into PID 1, and switches away forever. The scheduler later
runs on another stack and page table, where it can release the dead kernel
stack, user pages, private page tables, and descriptor references. It then
publishes the small reapable record and wakes the parent. `waitpid` removes
that record only after successfully copying status; `EFAULT` therefore permits
a retry. This ordering prevents freeing the currently active stack or page
table and prevents partially visible exit results.

## Acceptance

`/init` checks the initial argument/environment stack and PID 1, then exercises:

- cross-page writes and rejected user pointers;
- failed lookup and malformed-ELF exec without damaging the old image;
- fork, child exec with checked arguments/environment, exit, and waitpid;
- an invalid wait status pointer followed by a successful retry;
- eager-copy independence of a writable BSS page;
- RX text, kernel-address, and illegal-instruction faults confined to children;
- orphan adoption and collection by PID 1;
- `ECHILD` after every descendant has been collected.

Before starting PID 1, a kernel-side test exhausts physical memory and returns
one page at a time. Each failed or successful ELF construction must restore
the exact page count for its starting budget, proving rollback at multiple
allocation points.

The kernel waits until PID 1's runtime resources are reaped and verifies that
the physical-page count returns to its pre-init baseline. `make test` requires
`M5 PASS` with both 256 MiB and 32 MiB of RAM.
